# Product Discovery V0.3 — Teaching Intelligence & Command Model

**Status:** LOCKED  
**Locked:** 4 September 2026

## 1. Fundamental architecture principle

> **LLM interprets. Engines decide. Backend owns the truth.**

The LLM must not directly own classroom state or generate uncontrolled UI.

Flow:

```text
Voice / Touch / Ink
        ↓
AI Understanding
        ↓
Structured TeachingAction
        ↓
Backend Teaching Engine
        ↓
Validation
        ↓
Classroom State
        ↓
TeachingScene
        ↓
Renderer
```

## 2. TeachingAction

Natural teacher language is normalized into a structured action.

Example:

Teacher:

> “Buat satu soal seperti tadi tapi sedikit lebih sulit.”

Conceptual output:

```json
{
  "intent": "GENERATE",
  "target": {
    "reference": "CURRENT_QUESTION"
  },
  "constraints": {
    "difficulty": "INCREASE_ONE_LEVEL",
    "topic": "INHERIT",
    "grade": "INHERIT"
  },
  "presentation": {
    "showAnswer": false
  }
}
```

## 3. MVP intent taxonomy

Locked intents:

1. `GENERATE`
2. `MODIFY`
3. `EXPLAIN`
4. `DICTATE`
5. `ASK`
6. `NAVIGATE`
7. `PRESENTATION_CONTROL`
8. `CANVAS_CONTROL`
9. `ASSESS`
10. `SESSION_CONTROL`
11. `MEDIA_CONTROL`

## 4. Reference resolution

The system resolves natural references in this priority:

```text
Explicit selection
      ↓
Active object
      ↓
Current scene
      ↓
Last modified object
      ↓
Last generated object
      ↓
Recent teaching history
```

Examples:

- “yang tadi”
- “yang kedua”
- “ini”
- “itu”
- “yang terakhir”

If ambiguity remains materially high, the system asks the teacher instead of guessing.

## 5. Public vs private semantics

Output visibility is a first-class concept:

- `PUBLIC`
- `PRIVATE_TEACHER`
- `SYSTEM`

Example:

Teacher:

> “Jawabannya berapa?”

Default output:

- private teacher device.

Teacher:

> “Tampilkan jawabannya.”

Output:

- classroom display.

This prevents accidental answer leakage to students.

## 6. Dictation

When the teacher says:

> “Tuliskan…”

the system treats it as board content, not a conversational response.

Example:

> “Tuliskan rumus luas segitiga.”

can become:

```text
L = ½ × a × t
```

on the classroom canvas.

## 7. Classroom context

Context is structured, not only a chat history.

```text
CLASSROOM CONTEXT
│
├── Teacher Context
├── Class Context
├── Curriculum Context
├── Lesson Context
├── Scene Context
├── Interaction Context
└── Recent Action Context
```

Persistent and temporary context must be separated.

## 8. TeachingScene

AI-generated classroom content is represented as structured data.

The LLM must **not** generate arbitrary classroom HTML.

Initial scene types:

- `TITLE`
- `CONCEPT`
- `EXAMPLE`
- `QUESTION`
- `EXPLANATION`
- `DISCUSSION`
- `SUMMARY`
- `FREE_CANVAS`

Initial object families:

- text;
- mathematics;
- fraction;
- triangle;
- rectangle;
- square;
- circle;
- arrow;
- label;
- highlight;
- image/reference visual when required.

The renderer owns:

- visual design;
- typography;
- layout;
- animation;
- responsive behavior.

## 9. Annotation separation

Generated content and teacher/student digital ink are separate layers.

```text
TeachingScene
   ├── Generated Layer
   └── Annotation Layer
```

This enables commands such as:

- clear annotations;
- erase student answer;
- retain lesson scene.

## 10. Handwriting assessment

Handwriting is interpreted only when requested.

Flow:

```text
Relevant ink
   ↓
Vision / handwriting interpretation
   ↓
Structured math candidate
   ↓
Math validator
   ↓
Private teacher result
```

Default assessment result:

> **Private teacher device first.**

## 11. Mathematics validation

Deterministic mathematics must be validated by a math engine whenever possible.

The LLM may:

- interpret language;
- generate context;
- propose questions;
- explain concepts.

The engine should decide deterministic correctness.

## 12. Question reveal state

A generated question should ideally already include:

- question;
- answer;
- solution steps;
- hints.

These are hidden/revealed through state.

Example:

```text
Question visible
Hint 1 hidden
Hint 2 hidden
Step 1 hidden
Step 2 hidden
Answer hidden
```

Therefore commands such as “langkah berikutnya” can be instantaneous without a new model call.

## 13. Approval mode

Approval applies primarily to **generative actions**.

Navigation and basic controls should not require approval.

Examples that execute directly:

- next;
- back;
- show/hide;
- undo;
- clear non-destructive annotation where appropriate.

Destructive actions still require explicit confirmation.

## 14. AI suggestions

MVP suggestions may only use evidence the system actually knows.

Valid signals:

- teacher repeatedly asks for simpler explanations;
- prerequisite mismatch;
- teacher skips sections;
- lesson time remaining is low.

The AI must not claim students do not understand unless there is actual student-response evidence.

## 15. Curriculum grounding

Curriculum context comes from a controlled, versioned curriculum dataset.

It must not rely solely on model memory.

## 16. Student privacy

MVP excludes:

- student accounts;
- continuous classroom microphone;
- camera;
- student voice recording;
- persistent student identity.

Students may interact directly with the classroom canvas without an account.

## 17. Preparation vs live teaching behavior

Context determines generation behavior.

### Preparation

A request such as:

> “Buatkan materi tentang pecahan kelas lima.”

generates a broader lesson draft.

### Teaching

The same request during an active classroom session generates the most contextually relevant scene/action for the current teaching flow.

This contextual behavior is the locked default.
